功能

双登录方式

① OAuth 设备授权（PKCE，浏览器授权，dt- 30 天 + drt- 1 年自动旋转）② PAT 导入（pt-，长期有效兜底）——两家族可共存于同一 auth 文件。

登录自动领包

OAuth 登录成功后自动判断并领取一次性 Pro 升级包（eligibility → claim）。

COSY 推理

RSA 包 AES 会话密钥 + MD5 请求签名，纯 Go 实现，对接 gateway.qoder.com.cn SSE 流式。

图片输入

支持 OpenAI image_url 和 Anthropic image 块；自动上传到 Qoder 再以 messages[].image_url 发送。png/jpeg/gif/webp，单图 ≤10MB，最多 5 张。

动态模型

COSY 拉取 /algo/api/v2/model/list（chat scene），14 静态模型兜底；只暴露 Qwen / DeepSeek 系列。

每日签到

面板手动签到（单账号 / 批量）+ 10:00 / 21:00 定时自动签到，签到后返回最新积分快照。

积分面板

账号卡片：昵称 / 积分 / 计划 / 签到状态 / 操作（签到 / 刷新 / 选用），外加最近 20 条调用记录。

token 保活

22:00 定时刷新；按 token 前缀路由（drt- → deviceToken/refresh，jrt- → jobToken/refresh），PAT 永不劫持 OAuth 刷新。

auth 隔离：文件名前缀 qoderwork- 过滤，与 workbuddy 等其他插件互不干扰。

模型只暴露 Qwen + DeepSeek

GLM 走 workbuddy-cpa；Auto / GLM / Kimi / MiniMax 不会出现在 qoderwork 的模型列表里，executor 也会拒绝非 Qwen/DeepSeek 请求。 模型清单由 COSY 动态拉取，静态表仅作冷启动兜底。

安装

前置：运行中的 CLIProxyAPI（带 CGO / 插件支持）。

从 Release（推荐）

# 按你的平台下载（示例 linux/arm64）
unzip qoderwork_0.4.1_linux_arm64.zip
cp qoderwork.so /path/to/cliproxyapi/plugins/qoderwork.so

从源码编译

cd qoderwork
CGO_ENABLED=1 go build -buildmode=c-shared -ldflags "-X main.version=0.4.1" -o qoderwork.so .
cp qoderwork.so /path/to/cliproxyapi/plugins/

config.yaml

plugins:
  enabled: true
  dir: "plugins"
  configs:
    qoderwork:
      enabled: true

# 模型别名（可选）
oauth-model-alias:
  qoderwork:
    - name: qmodel_preview
      alias: qoder/qwen3.8-max
    - name: qmodel_latest
      alias: qoder/qwen3.7-max

登录

方式一 · OAuth（推荐）

CPA 管理面板 → Auth 文件 → QoderWork OAuth 登录卡片 → 浏览器打开授权链接 → 登录 qoder.com.cn（阿里云 SSO）→ 点 Continue 授权。插件自动轮询拿 token 落盘（dt-/drt-），并自动领取 Pro 升级包。

方式二 · PAT 导入

qoder.com.cn → 设置 → Personal Access Token → 创建（pt- 开头）→ 插件面板右上角「导入 QoderWork 凭证」→ 粘贴 → 导入。插件自动换 jobToken（jt-/jrt-）落盘。

面板地址：/v0/resource/plugins/qoderwork/panel（需 management key）。

每日签到每天领 100 Credits

签到走 Qoder 新版 campaign 接口：/sash/api/v1/me/campaigns + /campaigns/{id}/claim， 每日 10:00（UTC+8）刷新「每天领 100 Credits」；旧 /daily-check-in 仅作 fallback。 面板可单账号签到，也可「全部签到」批量执行。

设备指纹：上游遇到未知的 Cosy-MachineToken 会返回 HTTP 200 + 空活动列表（不报错）， 面板于是显示「当前账号无可用签到活动」。插件默认不发送任何机器头——此时上游正常下发活动。 若要领取仅对真实设备下发的活动，在装了 Qoder CN 客户端的机器上运行 ./scripts/detect_fingerprint.sh， 把输出填进插件配置即可（输出含设备 token，不要外传）： 
plugins:
  configs:
    qoderwork:
      checkin_fingerprint: '{"machine_id":"...","machine_token":"...","machine_type":"..."}'

必填 machine_id / machine_token / machine_type；字段不全时整体忽略该配置，不会发出半截指纹。

凭证家族与刷新

字段说明
accessTokendt-（OAuth，约 30 天）或 jt-（PAT 交换，24 小时）
refreshTokendrt-（约 1 年，自动旋转）或 jrt-（48 小时）
personalTokenpt-（长期兜底，导入即永久）
  • 刷新路由按 refreshToken 前缀：drt- → deviceToken/refresh；jrt- → jobToken/refresh → 失败回退 PAT re-exchange。
  • personalToken 永不主动覆盖活跃 token，只做最终兜底。
  • 宿主 15 分钟 auto-refresh + 插件 22:00 keepalive 均按此规则。

在带工具的 Agent 中使用客户端模式

请求里带 tools 时，插件自动进入客户端模式：使用客户端自己的 system prompt 和工具定义， 不再注入 Qoder 的 baseprompt system 与 14 个内置工具；完整保留 assistant.tool_calls 与 role:"tool" 的 tool_call_id，支持并行工具调用和工具结果续跑。 工具预算为最多 64 个 / 128KB，超出部分截断。

已通过 CPA 两条入口实测：OpenAI /v1/chat/completions 和 Anthropic /v1/messages 均能完成「工具调用 → tool_result → 最终回答」的完整闭环（qwen3.8-max / deepseek-v4-pro / deepseek-v4.1-flash）。
